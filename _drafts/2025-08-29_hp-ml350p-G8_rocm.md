This guide documents the process of configuring an HP ProLiant ML350p Gen8 server to run multiple modern, power-hungry GPUs like the dual-GPU AMD Radeon Pro V340. The goal is to create a capable, cost-effective platform for ROCm-based machine learning or high-performance computing. This is an advanced project that goes far beyond the officially supported configurations for this server.

**Disclaimer:** ⚠️ This configuration is highly experimental. Modifying firmware (iLO4) carries a risk of bricking your device. Proceed at your own risk.

***

## 1. Hardware Requirements

Success hinges on selecting specific compatible components. The Gen8 platform has particular requirements for enabling features needed by modern GPUs.

### 1.1. System: HP ProLiant ML350p Gen8

This dual-socket tower/rack server is the foundation. It offers a large number of PCI-e slots and a robust power delivery system, but requires significant modification to its cooling and firmware.

### 1.2. CPU: Ivy Bridge-EP (Xeon E5-2600 v2 Series)

This is a **mandatory requirement**. The v2 Xeons are necessary for **PCI-e Atomics Support**, which is critical for ROCm and proper GPU-to-GPU communication. The older Sandy Bridge (v1) CPUs lack this feature.

* **Best Single-Core Performance:** `E5-2673 v2` (8 Cores @ 3.30 GHz Base, 4.00 GHz Turbo). Ideal for tasks that don't scale perfectly across many cores.
* **Best Multi-Core Performance:** `E5-2697 v2` (12 Cores @ 2.70 GHz Base, 3.50 GHz Turbo). Best for highly parallelized workloads.
* **Best Value:** `E5-2680 v2` / `E5-2670 v2` (10 Cores). These often provide the best performance-per-dollar on the second-hand market.

Install **two CPUs** for access to all PCI-e slots and maximum memory bandwidth.

### 1.3. RAM: DDR3-1866 LRDIMM

To achieve maximum memory bandwidth, populate all memory channels for both CPUs with **DDR3-1866 LRDIMMs**. LRDIMMs (Load-Reduced DIMMs) allow for higher capacities and speeds in multi-DIMM configurations compared to standard RDIMMs.

### 1.4. GPU: AMD Radeon Pro V340

The Radeon Pro V340 is a dual-GPU card based on the Vega architecture, offering a massive 32GB of HBM2 memory. This guide is tailored to them, but the principles apply to other large BAR, high-power GPUs.

### 1.5. Power & Cooling

* **PSUs:** You will need two high-wattage PSUs, such as the **750W (P/N: 660185-001)** or **1200W (P/N: 660185-001)** models.
* **Fans:** The default fan configuration is insufficient. You must install the **High Performance Fan Kit (P/N: 661332-B21)** to prevent thermal throttling.

## 2. Hardware Installation & Power

### 2.1. GPU Slot Placement

For a dual CPU system, the PCI-e slots are mapped to specific CPUs (NUMA nodes). To ensure a GPU has direct access to its local CPU's memory controller, follow this layout:

* **CPU 1:** Manages the slots integrated into the main system board.
* **CPU 2:** Manages the slots on the PCI-e riser cage.

Place one V340 (or two single-GPU cards) attached to the CPU1 slots and the second V340 attached to the CPU2 riser slots. This minimizes latency by preventing data from having to cross the QPI link between the CPUs.

### 2.2. GPU Power Cabling (CRITICAL)

The ML350p G8 **does not use standard 10-pin GPU power connectors**. It uses **proprietary 8-pin connectors** on the Power Distribution Board (PDB). The wiring is non-standard but follows the EPS12V pinout for voltage and ground.

**DO NOT** plug a standard 8-pin PCI-e power cable into this connector; you risk destroying your hardware.

#### Option A: DIY Cables (Recommended)

You must create custom cables. The 8-pin connector on the PDB has the following pinout:

| Pin | Signal |
|-----|--------|
| 1   | +12V   |
| 2   | +12V   |
| 3   | +12V   |
| 4   | +12V   |
| 5   | Ground |
| 6   | Ground |
| 7   | Ground |
| 8   | Ground |

You will need to create a cable that goes from this 8-pin layout to two standard 8-pin PCI-e connectors for each V340. Use high-quality, thick-gauge wire (16AWG or 18AWG).

#### Option B: Pre-made Cables

You may be able to find pre-made cables from specialty vendors. Search for "HP ML350p G8 GPU Power Cable". Verify the pinout with a multimeter before use.

## 3. Firmware & BIOS Configuration

### 3.1. System BIOS Update

First, update your System ROM (BIOS) to the latest version. As of late 2023, the last stable release is **P72 v2019.05.24**. This can be downloaded from the HPE Support Center and flashed via the iLO4 interface. This version ensures maximum compatibility and stability for the required settings.

### 3.2. iLO4 Fan Control Mod

The default HP fan control algorithm will ramp fans to 100% speed upon detecting a third-party PCI-e card (like a GPU) and will not slow them down, creating excessive noise. A community-developed patch for **iLO4 firmware version 2.77** resolves this by enabling manual fan control.

1. **Download iLO4 v2.77:** Find the official `ilo4_277.bin` firmware file.
2. **Patch the Firmware:** Use the tools available at the [goliath-hp-ilo-fan-controller GitHub repository](https://github.com/GoliathLabs/goliath-hp-ilo-fan-controller). Follow the instructions there to patch the `.bin` file.
3. **Flash the Patched Firmware:** Upload the *patched* `.bin` file through the iLO4 web interface under `Administration -> Firmware`.
4. **Control Fans:** After flashing, you can control fan speeds via `ssh` into the iLO or using tools like `ipmitool`. For example, to set all fans to 20%:

    ```bash
    # raw 0x30 0x30 0x02 0xff is the "set all fans" command
    # 0x14 is 20 in hex
    ipmitool -I lanplus -H <ilo_ip> -U <user> -P <pass> raw 0x30 0x30 0x02 0xff 0x14
    ```

### 3.3. BIOS/UEFI Settings

Reboot the server and press **F9** to enter the System Utilities.

#### 3.3.1. Accessing the Hidden Service Menu

Many critical settings are hidden by default. In the main BIOS screen, press **`Ctrl+A`**. This will un-hide a new top-level menu item called **"Service Options"**.

#### 3.3.2. Enabling Core GPU Features

Navigate through the BIOS menus and configure the following settings:

* **System Options -> PCI-E Devices -> PCI Express 64-bit BAR Support:** **Enabled**
  * This is the "Large BAR" or "Resizable BAR" setting, essential for performance.
* **System Options -> Virtualization Options -> Intel(R) VT-d:** **Enabled**
  * Required for IOMMU and proper device isolation.
* **System Options -> SR-IOV:** **Enabled**
  * Enables Single Root I/O Virtualization.

#### 3.3.3. Disabling PCI-e Padding (RMRR)

This is the most critical and obscure step. HP Gen8 servers implement **Reserved Memory Region Reporting (RMRR)**, which can prevent multiple GPUs from initializing correctly or being used for passthrough/ROCm. The symptom is that not all GPUs will appear after boot. Disabling this requires using the `conrep` utility from within a running OS.

1. **Boot a Linux LiveCD:** Use a CentOS 7 LiveCD or install the HP Scripting Toolkit on your Arch install.
2. **Run `conrep`:**

    ```bash
    # First, save the current configuration
    ./conrep -s -f g8_config.xml

    # Edit the XML file and find the section for RMRR.
    # Change the setting from "Enabled" to "Disabled".
    # It might look something like this:
    # <Section name="Intel_VT_d_RMRR" helptext="Helptext">
    #   <Setting name="Intel VT-d RMRR" type="option" value="Disabled">
    #     ...
    #   </Setting>
    # </Section>

    # Load the modified configuration back into the BIOS
    ./conrep -l -f g8_config.xml
    ```

3. Reboot the server. All GPUs should now initialize correctly.

## 4. OS & ROCm Installation (Arch Linux)

### 4.1. Base Installation

Install Arch Linux as per the official installation guide. Ensure you are booting in **UEFI mode**.

### 4.2. ROCm Installation

ROCm packages are available in the Arch User Repository (AUR). Use an AUR helper like `yay` or `paru`.

```bash
# Update system and install an AUR helper if you don't have one
sudo pacman -Syu --needed git base-devel
git clone [https://aur.archlinux.org/yay.git](https://aur.archlinux.org/yay.git)
cd yay
makepkg -si

# Install the core ROCm stack
# This will pull in all necessary components like rocm-hip-sdk, rocm-opencl-sdk, etc.
yay -S rocm-utils
```

The V340 is a Vega10 GPU. While official support for Vega is waning, the open-source drivers often continue to work. You may need to set an environment variable to bypass the official "supported GPU" check in some applications:
`export HSA_OVERRIDE_GFX_VERSION=9.0.0`

### 4.3. Post-Installation

Add your user to the `render` and `video` groups to access the GPU devices without `sudo`.

```bash
sudo usermod -aG render,video $USER
```

Log out and log back in for the changes to take effect.

### 4.4. Verification

Check that the system correctly identifies all GPUs (remembering that each V340 has two).

```bash
# Should list all GPU devices and their properties
rocminfo

# Should show all available OpenCL platforms and devices
clinfo
```

## 5\. Performance Tuning: NUMA Pinning

With a dual-CPU, multi-GPU setup, ensuring a process runs on the correct CPU for the GPU it's using is critical for performance.

1. **Identify NUMA Nodes:**

    ```bash
    lscpu | grep NUMA
    # Output will show which CPU cores belong to which NUMA node (e.g., node0, node1)
    ```

2. **Identify GPU NUMA Affinity:**

    ```bash
    rocminfo
    # Look for the "NUMA node" property for each GPU.
    ```

    You should see that GPUs in the motherboard slots are on node 0, and GPUs in the riser are on node 1.

3. **Pin Processes with `numactl`:**
    Launch your compute tasks using `numactl` to bind them to the appropriate CPU and memory node. For a process that needs to use a GPU on NUMA node 1:

    ```bash
    # --cpunodebind=1: Only run on CPU cores in NUMA node 1
    # --membind=1: Only allocate memory from NUMA node 1
    numactl --cpunodebind=1 --membind=1 your_compute_application
    ```

Pinning your workload correctly can result in significant performance improvements by avoiding the slow QPI interconnect between the CPUs.
